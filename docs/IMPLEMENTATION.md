# 实现说明

## 边界与数据

React 显示本地界面。Electron 主进程统一负责验证、目录选择、依赖检测、子进程和结果校验。后台接入 YouTube、B站、抖音、小红书、X、TikTok、Vimeo、微博、微信视频号，并提供公共网页与 MP4/HLS/DASH 来源。平台身份和展示名集中于 `shared/platforms.ts`，链接与元数据适配位于 `electron/sources/`。

分享文案接受一个链接；B站保留分P，小红书保留必要分享参数。已知平台的 HTTP 分享短链接在请求前升级为 HTTPS，所有跳转逐跳校验协议、平台和主机，上限五次；响应读取有大小与时间限制。平台用户主页、合集、播放列表和任意主机链接由入口校验处理。

`contextIsolation`、`sandbox`、`webSecurity` 开启，`nodeIntegration` 关闭；不启用 webview，不允许新窗口、导航或网页权限。`app://clipkeep` 只提供打包资源，CSP 阻止界面连接网络，远程缩略图不会加载。

preload 公开固定的读取、任务、偏好、历史、会话方法和状态订阅。不暴露 ipcRenderer、shell、文件读取或通用命令执行。主进程校验 sender、主 frame、精确页面 URL 和输入结构。任务文件操作通过任务 ID 与输出序号定位，主进程检查路径归属、真实路径和符号链接；目录由系统选择器授予。“在浏览器中检查视频”复用相同平台链接校验。

元数据保留平台、公开页面地址、标题、可选时长、发布者、格式 ID、清晰度和条目选择。下载地址、签名分享参数、请求头与登录信息在主进程处理。B站校验分P；X 和微博区分帖子标识与媒体标识；通用网页绑定原始请求并使用安全摘要作为媒体标识。Vimeo 的私有分享路径在界面中还原为公开视频页面地址。多视频来源按照明确条目选择下载。

## 通用公共网络

通用网页使用公开访问模式，在界面和主进程同时限定登录授权范围。网络进程经本机鉴权代理发送 HTTP 与 HTTPS CONNECT；代理校验主机、端口、所有 DNS 结果及特殊地址范围，连接使用已经验证的固定 IP，跳转后的资源继续经过这一入口。代理凭据在内存中生成，操作完成时释放连接。

合成 DNS 全部返回 `198.18.0.0/15` 时，使用 Cloudflare HTTPS DNS 核实真实公共地址；查询包含域名，返回值继续执行公共 IP 校验。已验证地址按主机缓存一分钟并保持连接固定。普通私有或混合 DNS 响应保持原有阻断策略。

通用来源使用 yt-dlp 原生 HTTP/HLS/DASH 下载器；合并器、FFmpeg 和 ffprobe 输入限制为本地协议及受支持媒体格式。真实工具测试确认伪装本地播放列表触发零次外部资源请求。

## 子进程与认证

`spawn(executable, args, { shell: false })`，不拼接 shell 字符串。参数启用忽略配置、禁用插件目录、禁用缓存和自动更新。Node 的 JavaScript runtime 路径显式传给 yt-dlp。Chrome 模式只有用户主动勾选并点击操作后，才添加固定当前用户 Default 配置的 `--cookies-from-browser` 参数；没有 Cookie 导出参数。

任务使用独立进程组。取消先 SIGTERM，1.8 秒未退出再 SIGKILL；进程收尾前不接受重复任务。元数据读取有 90 秒超时；根据本机 yt-dlp 实测约 14 秒的冷启动，yt-dlp 检测上限为 30 秒，其他工具为 12 秒。版本检测忽略用户配置与插件。媒体子进程默认最多 12 小时，完整校验最多 1 小时。

登录开关随输入链接变更重置。私有分享地址冻结在任务创建时，当前界面读取其他视频后，原任务重试仍使用其原始来源。

## 文件与重试

每次新任务创建唯一子目录。原始媒体下载到 `.work/download.%(ext)s`，完成后从结构化 `after_move` 消息取得实际文件名，限定为任务目录内的普通文件。完成回执仅记录本地文件名、视频 ID 与格式选择，处理重试复用这一来源。其他编码使用 Matroska 合并后再整理为目标格式。

FFmpeg 探测实际轨道。兼容播放模式将媒体整理为 H.264 / AAC 的 MP4/M4A；原编码模式复制来源轨道并使用 MKV/MKA。纯音频从视频或独立音轨提取。校验通过后生成对应扩展名的 `.work/source.*`，并清理本轮完整原始副本。处理失败保留来源；媒体校验失败则改名留存，重试重新下载。取消后的 `.part` 留在原位置用于续传。

双输出先下载并验证视频，再使用 FFmpeg `-c:a copy` 提取音轨，不再次拉取音频。FFmpeg 使用 `-n`，各次提取保留不同临时文件。成果发布使用排他硬链接，不支持硬链接的卷采用 `COPYFILE_EXCL`，不覆盖同名文件。已经发布的 MP4 不因后续音频失败而删除。

ffprobe 流式扫描全部包，检查正时长、每轨包计数及轨道数量。兼容模式校验 H.264 / AAC，原编码模式校验来源编码轨道。扫描进度使用包时间，转换进度使用 FFmpeg 的媒体时间，SHA256 进度使用已读取字节；界面同时显示各阶段耗时。来源提供时长时检查 3 秒内误差；来源时长缺省时检查成品时长、轨道对应与完整包读取。ffprobe 有错误输出也判为失败。该检查覆盖完整包读取与音视频轨一致性。

队列、历史和偏好通过带版本的本地 JSON 保存，串行写入后原子替换，并保存最近有效备份。启动恢复任务列表，由用户点击继续队列。公开来源可重读，登录与捕获来源通过任务面板重新准备；有效的本地媒体可参与恢复处理。

调度领取任务和保存收尾状态与队列命令共用串行入口，入队保存成功后才启动任务。完成状态优先于同时到达的取消请求；收尾保存期间继续持有活动任务，写入失败回滚其他操作时保留其最新状态。重启后核对已选择格式的 ID 与尺寸，保留手选和已确认的原始画质；格式变化时要求重新确认。

工具输出使用流式 UTF-8 解码，以字节限制输出大小，并处理末尾的完整记录。进入媒体处理前检查当前工作目录与复用源文件的类型，符号链接进入文件检查流程。批量重读开始时清除上次准备结果，成功读取后恢复入队操作。

## 测试隔离

开发模式可以通过 `CLIPKEEP_TEST_MODE=1` 配合 `CLIPKEEP_TEST_ROOT` 使用模拟下载器。模拟模式在界面醒目标记并禁止 Chrome 登录态；它复用真实的主进程服务、IPC、文件流程与 FFmpeg/ffprobe。打包 App 的 `app.isPackaged` 强制关闭此入口，环境变量不能开启模拟模式。

官方参考：[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)、[yt-dlp 参数及嵌入说明](https://github.com/yt-dlp/yt-dlp#usage-and-options)。

## App 网页会话

`electron/access/` 管理抖音、Vimeo、X 的临时 Session、远程 WebContentsView、可信本地工具栏、会话授权和媒体响应捕获。远程页面采用沙箱与上下文隔离，工具栏拥有独立的窄 IPC 接口并核对主框架与窗口归属。会话网络经公网校验代理访问。

确认授权后，yt-dlp 从独立双向管道 `/dev/fd/3` 读取 Netscape Cookie 数据；域名、路径、HTTPS 与有效期随条目传入。用户代理和来源站点通过标准输入配置传入。子进程参数包含描述符路径，父进程消费结束时回写的 Cookie 数据。操作结束关闭管道。

捕获的签名 URL 由主进程保留，界面使用临时来源 ID 选择。捕获媒体沿用通用来源的原生下载器与本地后处理约束，公开信息保留原视频平台。任务冻结来源与会话 Runner；关闭网页登录窗口后可继续同一会话的下载与重试。清除会话终止对应授权。

媒体头探测保留当前网页的 ASCII UA、Referer 与会话，单次读取上限 512 KiB，支持操作取消。分离画面与音轨使用合成的私有格式描述，经额外内存管道 `/dev/fd/4` 传给 yt-dlp；原生下载后采用本地协议白名单合并。窗口关闭后临时代理与会话继续服务当前授权，清除会话时一起结束。

## 队列与历史

`electron/queue/` 管理任务、准备结果、顺序调度、恢复和 IPC；每份准备结果使用独立 DownloadService，分别固定来源与执行器。`electron/storage/` 保存白名单字段及设置快照；`src/features/tasks/` 提供批量添加、队列、历史和草稿状态。

状态沿用 done/running/failed/cancelled/cancelling，增加 queued/awaitingInput/interrupted。重新选择来源或改变输出使用新的工作目录代次。已有成果发布前核对文件内容，相符时登记恢复成果；冲突进入待处理。清除平台会话先收尾相关任务，其他可运行任务继续执行。

清晰度偏好按语义保存为最高可用、最高 1080p、最高 720p；原始画质由用户按任务确认。成品校验记录实际宽高与音轨。测试入口与验收条件见 [TESTING.md](TESTING.md)。


## 0.8.0 任务、设置与文件管理

当前任务区域保留本次启动中新增和操作的任务结果，历史按内容版本刷新并对搜索做 250 ms 防抖。`isReorderable` 是界面与主进程共同使用的排序约定：位置按等待序列计算。立即重试提升到等待队首并启动队列；重新排队遵循当前暂停状态。

批量读取、加入队列和移除操作共享条目成员集合。输入校验和读取异常进入面板消息；已移除条目退出后续读取与加入队列。设置状态通过独立请求生命周期读取，磁盘与维护状态分别显示读取结果，写操作继续共用串行入口。

任务记录保存已发布成果的文件名与 SHA256。重新准备来源复制成果路径、校验和与成果状态；成品移入废纸篓和移动后关联继续执行身份检查。文件组织支持平台、作者和日期，命名支持日期前缀。恢复文件默认保留 7 天，可选 0/30 天；启动和每小时处理过期文件。磁盘统计按 inode 区分共享硬链接与独占可释放内容。

清空历史使用 `privacy-pending.json` 持久化清理状态，再同步主文件与备份。启动时优先完成挂起的清理，结束后移除标记，成品继续保留。

## 工具维护与后台运行

工具检测由队列共享缓存，正常有效期为 5 分钟，准备状态有效期为 5 秒。路径、大小、修改时间和 inode 变化、手动检测或执行异常触发刷新。工具准备校验支持的版本及本机执行兼容性，已有安装按候选路径继续查找可用版本。

解析器升级从官方固定版本下载并核对 SHA256、版本与运行结果。升级前备份实际使用的随包、自选或应用内工具，并校验回退副本。切换工具后原子保存选择；选择提交失败时恢复原有效工具。应用安装包另行校验归档路径、应用标识、版本、架构、签名与公证。诊断导出采用白名单字段。

主窗口可隐藏并继续下载，Dock 展示进度和待处理数量。活动任务使用 `prevent-app-suspension`，结束时释放休眠保护与 Dock 状态。明确退出时保存队列并收尾会话；再次打开后显式继续。
